# Operations

Day-two Flux commands, debugging, and common platform pitfalls.

## Status at a glance

```bash
flux check
flux get ks
flux get hr -A
flux get sources all
flux get image all          # when image automation is in scope (dev)

# Anything not Ready
flux get ks | grep -v True
flux get hr -A | grep -v True
```

Watch continuous progress:

```bash
flux get ks --watch
flux get hr -A --watch
```

---

## Reconcile

Always refresh the **Git source** first when debugging “I merged but nothing happened”:

```bash
flux reconcile source git flux-system
flux reconcile ks apps --with-source
flux reconcile ks <kustomization-name> --with-source
```

Helm / OCI:

```bash
flux reconcile source oci <name> -n <namespace>
flux reconcile hr <name> -n <namespace> --with-source
```

## Debug & trace

```bash
# Controller errors
flux logs --level=error
flux logs --kind=kustomization --name=<name>
flux logs --kind=helmrelease --name=<name> --namespace=<ns>

# What owns an object / dependency graph
flux tree ks apps
flux trace helmrelease/<name> -n <namespace>
flux trace kustomization/<name>

# Events on a HelmRelease
kubectl describe helmrelease <name> -n <namespace>
kubectl get events -n <namespace> --sort-by='.lastTimestamp'
```

Controller pods (when CLI is not enough):

```bash
kubectl logs -n flux-system deploy/source-controller
kubectl logs -n flux-system deploy/kustomize-controller
kubectl logs -n flux-system deploy/helm-controller
kubectl logs -n flux-system deploy/image-automation-controller   # dev images
```

## ARC runner image

Wait jobs use `ghcr.io/ianoflynnautomation/actions-runner` (`images/actions-runner/Dockerfile`: `home-operations/actions-runner` plus Azure CLI).

Rebuild after bumping the `FROM` digest:

1. Merge the Dockerfile change to `main`.
2. `.github/workflows/publish-actions-runner.yml` pushes `:<runner-version>` (parsed from `FROM`).
3. Match that tag on the three HelmReleases in `kubernetes/apps/base/actions-runner-system/gha-runner-scale-set/app/`.

The runner namespace pulls GHCR via `ghcr-pull-secret` (same Key Vault `ghcr-pat` as the app). Make the GHCR package internal/private as you prefer; pods will not pull anonymous.

## Stuck Kustomization / HelmRelease

1. Read the Ready condition message: `flux get ks` / `flux get hr -A`.
2. Check **dependsOn** parents — if a parent is False, fix that first.
3. For Helm: `kubectl describe hr <name> -n <ns>` (upgrade/install failures, hooks, timeouts).
4. Workloads: `kubectl get pods -n <ns>` (Pending, CrashLoopBackOff, ImagePullBackOff).
5. Force reconcile source + KS/HR.
6. Unstick loop:

   ```bash
   flux suspend ks <name>
   flux resume ks <name>
   ```

Do **not** `kubectl delete` Flux-managed objects as a habit — Flux will recreate them. Prefer suspend, fix Git, or revert.

## Secrets

```bash
kubectl get externalsecret -A
kubectl describe externalsecret <name> -n <namespace>
kubectl get secretstore,clustersecretstore -A
```

Failures are often Workload Identity, Key Vault permissions, or missing keys — not Flux itself.

Preview environments (dev only) need two extra Key Vault secrets, written by `bjjeire-terraform-azurerm-aks` (`main.key-vault.tf`):

| Secret name | Used by | Notes |
|---|---|---|
| `github-preview-pat` | `ResourceSetInputProvider` `bjj-eire-prs` | Fine-grained PAT, Contents + Pull requests read on `BjjEire`. Pass to Terraform as `TF_VAR_github_preview_pat` (required on the dev environment). |
| `flux-preview-webhook-token` | GitHub `Receiver` `bjj-eire-prs` | HMAC generated by Terraform. Copy from Key Vault into the GitHub webhook secret only if the notification-controller hook is published; poll is the fallback. |

Without the PAT the ResourceSet stays empty (no **PR** envs). SHA/main acceptance uses Static `ResourceSetInputProvider` objects applied by CI (`bjjeire.io/sha-env=true`) and does not need the PAT. Full factory map: [bjj-eire-preview.md](bjj-eire-preview.md).

```bash
flux get resourceset -n flux-system
flux get resourcesetinputprovider -n flux-system
kubectl get ns -l bjjeire.io/ephemeral=true
```

Tear down a SHA env by deleting its Static InputProvider (Kyverno also reaps those after `janitor/ttl`, default 4h). Do not delete the namespace while the provider still exists — ResourceSet will recreate it.

## Common platform issues

| Symptom | Likely cause | Fix direction |
|---------|--------------|---------------|
| Outbound call fails from pod | No `ServiceEntry` (REGISTRY_ONLY) | Add host to `istio-egress/config/service-entries.yaml` |
| Ingress 404 / no route | Missing HTTPRoute or Gateway listener | Check routes + Gateway listeners in overlay/base |
| HTTPS route not accepted | Namespace missing `gateway-access: "true"` | Label namespace in Git |
| Workload not in mesh | Missing ambient label | Set `istio.io/dataplane-mode: ambient` (not sidecar injection) |
| LB health failing | HTTP probe on hostname router | Use TCP probes on Gateway service (already pattern in base) |
| cert-manager webhook issues on AKS | `webhook.url.host` set | Do **not** set that field |
| Drift storms on istiod | Drift detection too strict | Use `warn` for controllers that mutate themselves |
| Image tags not moving in stg/prod | By design | Promote via PR; automation is **dev only** |
| Chart not updating | Overlay pin / OCI source stale | Bump tag; `flux reconcile source oci …` |

## Suspend / resume

Useful during incidents or coordinated maintenance:

```bash
flux suspend ks <name>
flux suspend helmrelease <name> -n <namespace>

flux resume ks <name>
flux resume helmrelease <name> -n <namespace>
```

Document who suspended what; long-lived suspends hide drift.

## Rollback

1. **Git revert** of the bad commit (preferred).
2. Reconcile:

   ```bash
   flux reconcile source git flux-system
   flux reconcile ks apps --with-source
   ```

3. Break-glass only: suspend the HelmRelease, pin known-good tags in Git, resume, reconcile. See [releases.md](releases.md#rollback).

## Notifications

Flux `notification-controller` may be present (e.g. PodMonitor under flux extras) without a configured Provider/Alert. Until Slack/Discord/GitHub status is wired, rely on:

```bash
flux get hr -A -w
flux logs --level=error
```
